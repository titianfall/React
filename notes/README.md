## ⏱ [0장 준비하기](ch00.md)

- **HTML**은 웹사이트의 뼈대를 만드는 마크업 언어. 태그는 열었으면 반드시 닫는다 → [0.1](ch00.md#01-html-살펴보기)
- **`<head>`** 는 눈에 보이지 않는 정보(메타데이터), **`<body>`** 는 실제로 보이는 내용 → [0.1 ③](ch00.md#3-웹사이트의-뼈대를-구성하는-태그들)
- **SPA**는 HTML 파일 하나로 `<body>` 안의 콘텐츠만 갈아 끼우는 방식. 리액트가 이걸 도와준다 → [0.1 ④](ch00.md#4-spa-single-page-application)
- **CSS**는 겉모습 담당. 같은 HTML도 CSS만 바꾸면 전혀 다른 사이트가 된다 → [0.2](ch00.md#02-css란-무엇인가)
- **자바스크립트**는 동작 담당. 정식 명칭은 ECMAScript, 기준은 ES6, 동적 타이핑 언어 → [0.3](ch00.md#03-자바스크립트)

## ⏱ [1장 리액트 소개](ch01.md)

- 리액트 = **웹과 네이티브 UI를 위한 자바스크립트 라이브러리**. SPA를 쉽고 빠르게 만들어 준다 → [1.1](ch01.md#11-리액트는-무엇인가)
- **라이브러리 vs 프레임워크**의 차이는 흐름의 **제어 권한을 누가 갖느냐** → [1.1 ④](ch01.md#4-다양한-자바스크립트-ui-프레임워크)
- **Virtual DOM**으로 바뀐 부분만 찾아 실제 DOM에 반영 → 빠른 업데이트 → [1.2 ①](ch01.md#1-빠른-업데이트와-렌더링-속도)
- 장점 6가지: 렌더링 속도 · 컴포넌트 구조 · 재사용성 · 메타의 지원 · 커뮤니티 · React Native → [1.2](ch01.md#12-리액트의-장점)
- 단점 2가지: **방대한 학습량**, **높은 상태 관리 복잡도**(state가 늘수록 복잡해진다) → [1.3](ch01.md#13-리액트의-단점)

## ⏱ [2장 리액트 시작하기](ch02.md)

- **create-react-app(CRA)** 은 리액트 19 이후 **deprecated**. 개념과 역사만 알아둔다 → [2.1](ch02.md#practice-21-create-react-app으로-리액트-애플리케이션-생성하기)

- 실행은 `cd my-app` → `npm install` → `npm run dev`, 주소는 **localhost:5173** (CRA는 3000) → [2.2](ch02.md#step-2--패키지-설치-및-실행)

- CRA와 Vite의 차이는 생성 명령어 · 실행 명령어 · 포트 · 진입 파일 → [비교표](ch02.md#create-react-app-vs-vite-정리)

## ⏱ [3장 JSX](ch03.md)

- **JSX = JavaScript + XML/HTML**. 자바스크립트의 **확장 문법**(A syntax extension to JavaScript) → [3.1](ch03.md#31-jsx란)
- JSX는 결국 **`React.createElement()` 호출로 변환**된다. 즉 최종 결과물은 자바스크립트 → [3.2](ch03.md#32-jsx의-역할)
- 장점 3가지: **코드 간결 · 가독성 향상 · Injection Attack(XSS) 방어** → [3.3](ch03.md#33-jsx의-장점)
- HTML 사이에 **중괄호 `{}`** 를 쓰면 그 안은 무조건 **자바스크립트 코드**(변수 · 함수 호출 · 속성값) → [3.4](ch03.md#34-jsx-사용법)
- 상위 태그가 하위 태그를 감싸면 그게 곧 **children** → [3.4 children 정의하기](ch03.md#children-정의하기)

## ⏱ [4장 엘리먼트 렌더링](ch04.md)

- **엘리먼트 = 리액트 앱을 구성하는 가장 작은 빌딩 블록.** 화면에 보일 내용을 **기술(describe)** 한다 → [4.1 ①](ch04.md#1-엘리먼트의-정의)
- **리액트 엘리먼트(Virtual DOM) ≠ DOM 엘리먼트(브라우저 DOM).** 전자는 후자의 **가상 표현**이다 → [4.1 ①](ch04.md#1-엘리먼트의-정의)
- 엘리먼트는 `type` · `props`(그 안에 `children`)를 가진 **평범한 자바스크립트 객체**다 → [4.1 ②](ch04.md#2-엘리먼트의-생김새)
- 렌더링은 **`createRoot(root DOM node).render(element)`**. HTML에는 `<div id="root">` 하나만 있으면 된다 → [4.2](ch04.md#42-엘리먼트-렌더링하기)
- 엘리먼트는 **불변(immutable)**. 업데이트하려면 **새로 만들어 바꿔치기**한다 → [4.3](ch04.md#43-렌더링된-엘리먼트-업데이트하기)

## ⏱ [5장 컴포넌트와 Props](ch05.md)

- 리액트는 **컴포넌트 기반(Component-Based)**. 작은 컴포넌트가 모여 페이지 전체를 구성한다 → [5.1](ch05.md#51-컴포넌트에-대해-알아보기)
- 컴포넌트는 **함수**와 같다. **입력 = props, 출력 = 리액트 엘리먼트** → [5.1](ch05.md#51-컴포넌트에-대해-알아보기)
- **props는 읽기 전용(Read-Only)**. 모든 컴포넌트는 props에 관해 **Pure 함수처럼** 동작해야 한다 → [5.2 ②](ch05.md#2-props의-특징)
- **컴포넌트 이름은 반드시 대문자로 시작**한다. 소문자면 리액트가 **DOM 태그로 인식**한다 → [5.3 ④](ch05.md#4-컴포넌트-이름-짓기)
- 여러 컴포넌트를 합치면 **합성**, 큰 컴포넌트를 쪼개면 **추출**. 쪼갤수록 **재사용성**이 올라간다 → [5.4](ch05.md#54-컴포넌트-합성) · [5.5](ch05.md#55-컴포넌트-추출)
