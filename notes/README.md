## ⏱ [0장 준비하기](ch00.md)

- **HTML**은 웹사이트의 뼈대를 만드는 마크업 언어. 태그는 열었으면 반드시 닫는다 → [0.1](ch00.md#01-html-살펴보기)
- **`<head>`** 는 눈에 보이지 않는 정보(메타데이터), **`<body>`** 는 실제로 보이는 내용 → [0.1 ③](ch00.md#3-웹사이트의-뼈대를-구성하는-태그들)
- **SPA**는 HTML 파일 하나로 `<body>` 안의 콘텐츠만 갈아 끼우는 방식. 리액트가 이걸 도와준다 → [0.1 ④](ch00.md#4-spa-single-page-application)
- **CSS**는 겉모습 담당. 같은 HTML도 CSS만 바꾸면 전혀 다른 사이트가 된다 → [0.2](ch00.md#02-css란-무엇인가)
- **자바스크립트**는 동작 담당. 정식 명칭은 ECMAScript, 기준은 ES6, 동적 타이핑 언어 → [0.3](ch00.md#03-자바스크립트)

## ⏱ [1장 리액트 소개](ch01.md)

- 리액트 = **웹과 네이티브 UI를 위한 자바스크립트 라이브러리**. SPA를 쉽고 빠르게 만들어 준다 → [1.1](ch01.md#11-리액트는-무엇인가)
- **라이브러리 vs 프레임워크**의 차이는 흐름의 **제어 권한을 누가 갖느냐** → [1.1 ④](ch01.md#4-다양한-자바스크립트-ui-프레임워크)
- **Virtual DOM**으로 바뀐 부분만 찾아 실제 DOM에 반영 → 빠른 업데이트 → [1.2 ①](ch01.md#1-빠른-업데이트와-렌더링-속도)
- 장점 6가지: 렌더링 속도 · 컴포넌트 구조 · 재사용성 · 메타의 지원 · 커뮤니티 · React Native → [1.2](ch01.md#12-리액트의-장점)
- 단점 2가지: **방대한 학습량**, **높은 상태 관리 복잡도**(state가 늘수록 복잡해진다) → [1.3](ch01.md#13-리액트의-단점)

## ⏱ [2장 리액트 시작하기](ch02.md)

- **create-react-app(CRA)** 은 리액트 19 이후 **deprecated**. 개념과 역사만 알아둔다 → [2.1](ch02.md#practice-21-create-react-app으로-리액트-애플리케이션-생성하기)
- 새 프로젝트는 **Vite**로: `npm create vite@latest my-app -- --template react` → [2.2](ch02.md#practice-22-vite로-리액트-애플리케이션-생성하기)
- 실행은 `cd my-app` → `npm install` → `npm run dev`, 주소는 **localhost:5173** (CRA는 3000) → [2.2](ch02.md#step-2--패키지-설치-및-실행)
- **HMR**: 코드를 저장하면 전체 새로고침 없이 **바뀐 모듈만 교체** → 상태가 유지된다 → [2.2 NOTE](ch02.md#note--hot-module-replacement-hmr)
- CRA와 Vite의 차이는 생성 명령어 · 실행 명령어 · 포트 · 진입 파일 → [비교표](ch02.md#create-react-app-vs-vite-정리)

## 노트 쓰는 규칙 (요약)

새 장을 정리할 때는 [CLAUDE.md](../CLAUDE.md)의 규칙을 따른다. 핵심만 옮기면:

1. 노트 최상단에 **`⏱ 30초 요약`** — 5줄 이내, 각 줄이 본문 절로 링크
2. 노트 하단에 **이전 / 다음 장 네비게이션**
3. **이 인덱스 파일도 같이 갱신** — 두 곳의 요약이 어긋나면 안 된다
4. 장 사이에 이어지는 개념은 상대 경로 링크로 연결 (예: 1장의 SPA → 0장 SPA 절)
